1
Welcome Screen
First impression. Patient has downloaded the app after receiving their Freischaltcode. Goal: communicate what MindBridge is and why it's worth setting up — in under 10 seconds.
Layout Notes
Hero illustration fills top ~40% of screen — no text, reduces cognitive load on first open
App logo + name below image — establishes brand before asking for anything
Two CTAs: primary "Get started" + ghost "I already have an account" — handles both new and returning users
Language switcher visible before any action — critical for multilingual patient base (Turkish, Arabic, Russian in Germany)
No login wall on first open — patient should see value before being asked to create an account
Design Decisions
Illustration style TBD — must be calm, non-clinical, culturally neutral
Avoid medical imagery (brain scans, pills, hospital) — stigma risk in mental health context
Heading copy placeholder: "Your mental health programme, prescribed for you" — to be validated with patients

2
Freischaltcode Entry
Highest drop-off screen. Patient must manually enter a 16-character code they received from their doctor — often on paper. Every friction point here costs an activation.
Layout Notes
Progress bar at top — 1/8 steps. Patient needs to see this is a short process
Code input split into 4 groups of 4 — matches how codes are printed on paper. Auto-advance between groups.
Help tooltip: "Where is my code?" — opens a visual guide showing the paper format
Error state placeholder visible in wireframe — must be designed before development (E1: invalid, E2: expired)
Camera/scan option for code (future enhancement) — not in v1 but reserve layout space
Critical UX Rules
Auto-capitalise + strip spaces — codes are case-insensitive but often have formatting inconsistencies
Numeric keyboard if code is numeric — do not default to QWERTY
Show remaining character count per group
After 3 failed attempts → show KK helpline number prominently

Account Creation
Patient creates their MindBridge account. SSO via Krankenkasse login reduces friction and pre-populates patient data where available.
Layout Notes
KK SSO button at top — primary path. Most patients have a GKV app login already
"Or" divider before email/password — secondary path for patients without KK app
Password strength indicator — 4-segment bar, real-time feedback
Fields: Email · Password · Confirm password — keep minimal. Name collected in intake survey.
Returning user path: "I already have an account" → login screen (no re-entry of code required)

4
DSGVO Consent
Mandatory under GDPR/DSGVO and BfArM DiGA certification. The single most common cause of unnecessary onboarding abandonment — when mandatory and optional consents are visually indistinguishable.
Layout Notes
REQUIRED and OPTIONAL sections visually separated — critical distinction, not just a label
Required items pre-checked — patient must actively uncheck to refuse (legally valid, reduces friction)
Optional items unchecked by default — ePA sync, analytics, research participation
Plain-language summary box below each consent — not just legal text. Tested with B1-level German speakers.
CTA button: "Continue" not "I agree to all" — framing matters in mental health context
Error State — Mandatory Refused
If patient unchecks a required item → inline explanation appears: "This is required to use MindBridge. Here's why:"
Never say "You cannot proceed" — reframe as informational

5
Health Intake — Part 1
First intake screen — one question per screen pattern. Reduces abandonment vs long-form surveys. This screen captures primary diagnosis / condition type.
Layout Notes
One question per screen — reduces overwhelm. Progress dots show position within intake section.
Radio button options — tap to select, visual feedback (filled + background highlight)
Back + Continue navigation — patient can revise answers without restarting
"Skip this question" available for optional items — never block on optional data
Question copy: plain language, not clinical. "How would you describe what you're experiencing?" not "Primary DSM-5 diagnosis"

6
Health Intake — Symptom Severity
Captures current symptom severity using a visual slider + emoji scale. Used to calibrate programme intensity. Optional free-text for patient to describe in their own words.
Layout Notes
5-point emoji scale above slider — visual anchors reduce misinterpretation of scale direction
Slider with thumb visible — shows current selection clearly. Haptic feedback on mobile.
Text labels "Not at all" / "Extremely" must be validated for cultural translation — some languages invert scale expectations
Optional free-text field below — "Tell us more in your own words (optional)". Max 200 chars.
Emoji icons TBD — must be culturally neutral, avoid Western-specific facial expressions

7
Programme Preview
Patient sees their personalised programme before committing. Reduces drop-off by setting expectations. "Adjust" option lets them modify without restarting intake.
Layout Notes
Programme card — name, type (CBT / mindfulness / hybrid), duration, session frequency, estimated daily time
"What's included" list — 3 key features, icon + label format. Max 3 items — don't overwhelm.
"Adjust programme" ghost button — opens intensity/frequency preferences without re-doing intake
No HCP information visible here — don't remind patient this is a medical device at moment of commitment
Progress bar = 87% — patient must feel almost done at this point. Seeing high progress increases completion.

8
Onboarding Complete — You're Ready
Final onboarding screen. Patient has completed all steps. Goal: celebrate completion, set up notifications, and launch the first session with momentum — not bureaucracy.
Layout Notes
Celebration zone at top — illustration or animation (lottie). Communicates success clearly before any text.
Notification permission prompt — inline card, not OS alert. Explain why before triggering system dialog.
Primary CTA: "Start your first session" — launch into programme immediately. High first-session rate = better 30-day retention.
Secondary: "Explore first" — let patient look around the app without starting
Small note at bottom: "Your doctor receives a summary of your progress" — transparency on data sharing. Do not hide this.
Retention Design Note
Research on DTx apps: patients who complete a session within 24h of onboarding have 3× the 30-day retention rate. This screen must funnel to first session — not to settings, not to a tour.
